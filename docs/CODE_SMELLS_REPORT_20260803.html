Code Smells Report — code_puppy Core

Generated by a 3-part audit (SMELL_1, SMELL_2, SMELL_3). Research-only — no source files were modified to produce this report.

Executive Summary

The codebase is functionally solid but shows a consistent, repo-wide pattern: breadth over depth — instead of a few catastrophically broken functions, nearly every module in scope is a God Module/God Class that grew past its original single responsibility, and several near-identical patterns are hand-copied instead of abstracted. The five most severe findings, in order of impact: (1) code_puppy/command_line/ hosts 10 *_menu.py files (~8,000+ lines) that bypass the project’s own register_screen plugin hook — a direct, citable violation of AGENTS.md’s plugin-vs-core golden rule, especially glaring since 7+ newer features (skills, hooks, spinner, steer-queue, theme, plugin-list, prune) already use that exact hook correctly; (2) code_puppy/config.py is a 2944-line God Module with ~153 unrelated free functions covering everything from XDG paths to a self-contained quick-resume subsystem; (3) code_puppy/tools/common.py’s _get_user_approval_impl/_get_user_approval_async_impl are ~160-180 line near-duplicate twins with a correctness risk baked in — a TUI-mode fix was added to only one of the two copies; (4) code_puppy/model_factory.py’s ModelFactory.get_model() is a ~472-line if/elif type-dispatch chain that violates Open/Closed — every new provider requires editing this one method; and (5) code_puppy/messaging/rich_renderer.py’s RichConsoleRenderer is a god-class with ~35 _render_* methods, the largest a self-admittedly-complex 141-line method. Across all three audit passes, every single file explicitly named in scope violates AGENTS.md’s own 600-line hard cap (Rule #3), confirming this isn’t isolated to one directory but a systemic tech-debt pattern. On the positive side: exception handling, while broad (except Exception:), is almost always deliberate and commented; no bare except:, no dead imports, and no test-sniffing hacks were found anywhere in scope except one isolated sys.modules check in config.py.

Methodology

Scope: core modules only — code_puppy/ root files, code_puppy/agents/, code_puppy/tools/, code_puppy/mcp_/, code_puppy/command_line/, and code_puppy/messaging/. Explicitly excludes code_puppy/plugins/, code_puppy/tui/, and tests/.

Approach: a three-part audit run sequentially (SMELL_1: core root + agents/; SMELL_2: tools/ + mcp_/; SMELL_3: command_line/ + messaging/, plus final consolidation). Each part used: (a) a line-count scan (wc -l) to identify files over the 600-line cap, prioritizing the largest; (b) targeted full/partial reads of the largest files to map class/function structure and identify long-method, god-class, and duplication smells; (c) grep-based pattern search for except Exception:/bare except:, magic numbers, TODO/FIXME, and cross-directory imports to check layering; (d) ruff check --select F401,F841 to confirm no dead imports/unused variables; (e) for SMELL_3 specifically, a direct read of AGENTS.md’s golden rule and code_puppy/callbacks.py’s hook inventory to check which command_line/ features should have been plugins.

Architecture Rule Violations

AGENTS.md’s golden rule: “nearly all new functionality should be a plugin under code_puppy/plugins/ that hooks into core via code_puppy/callbacks.py. Don’t edit code_puppy/command_line/.” Two distinct, independently-citable violations were found:

  1. Plugin-vs-core golden rule — the *_menu.py family. code_puppy/callbacks.py ships a register_screen hook (() -> list[dict] with {"command": str, "open": callable(app)}) built specifically so new full-screen menus can be contributed as opt-in plugin screens. It is actively and correctly used by 7+ newer features: plugins/agent_skills/skills_tui.py, plugins/hook_manager/hooks_tui.py, plugins/puppy_spinner/spinner_tui.py, plugins/steer_queue/queue_tui.py, plugins/plugin_list/plugins_tui.py, plugins/theme/register_callbacks.py, plugins/prune/prune_tui.py. Yet 10 older *_menu.py files (add_model_menu.py, model_settings_menu.py, autosave_menu.py, uc_menu.py, diff_menu.py, judges_menu.py, mcp_binding_menu.py, colors_menu.py, agent_menu.py, set_menu.py — ~8,000+ combined lines) live directly in code_puppy/command_line/ and are imported eagerly for side effects (e.g. command_handler.py: import code_puppy.command_line.uc_menu # noqa: F401) rather than through the hook system. This is the single strongest, most concrete violation across the entire 3-part audit — the exact extension point exists, is proven in production by other features, and is simply not being used here. Remediation: migrate each menu to a code_puppy/plugins/<menu_name>/ package registering via register_screen, one at a time, starting with the smallest/newest (colors_menu.py, mcp_binding_menu.py) before attempting the largest (add_model_menu.py, model_settings_menu.py).

  2. 600-line hard cap (Rule #3). AGENTS.md’s Rules section states a “600-line hard cap — split into submodules” as an explicit, numbered rule — not a style preference. Every file explicitly named across all three SMELL sub-audits’ SCOPE sections violates it: config.py (2944), tools/common.py (1760), tools/command_runner.py (1603), cli_runner.py (1538), callbacks.py (1395), messaging/rich_renderer.py (1364), command_line/add_model_menu.py (1413), command_line/model_settings_menu.py (1361), mcp_/server_registry_catalog.py (1126), agents/_runtime.py (1152), model_factory.py (1140), and more. This is a second, independently-citable architecture-rule violation, distinct from (but compounding) the plugin/core golden-rule violation above — it confirms the tech debt is systemic across the whole audited surface, not confined to command_line/.

  3. Minor core→plugins layering reaches (lower severity, noted for completeness): code_puppy/callbacks.py (core) imports code_puppy.plugins.config.get_disabled_plugins; code_puppy/config.py imports code_puppy.plugins.statusline.payload.detect_git_branch; code_puppy/model_factory.py imports OAuth utilities from plugins.claude_code_oauth/plugins.gemini_oauth. These go the opposite direction of the golden rule’s main concern (core depending on specific plugins rather than plugins depending on core) and would break silently if those plugins were ever renamed/removed. A on_resolve_oauth_credential callback hook, or relocating the shared utilities (detect_git_branch, get_disabled_plugins) to a neutral core-adjacent module, would close this gap.

  4. Separation-of-concerns within messaging/ vs command_line/. While not a golden-rule violation in the plugin sense, messaging/editor_completion.py and 5 sibling files reaching into command_line/*_completion modules inverts the expected “messaging is the lower-level UI substrate, command_line is a consumer” layering — a related, smaller-scope architectural smell worth fixing alongside the register_screen migration.
